Ch. 2 • Function calls

Leaf procedures

Lesson 1 / 9

A leaf procedure does not call another procedure. The calling convention places integer arguments in x10–x17 (x10–x17) and the return value in x10. The caller's return address is in x1 (x1). A leaf procedure can use caller-saved temporary registers without saving them for the caller, but must restore any callee-saved registers (x8–x9 and x18–x27) it modifies.

Inputs

x10 = g, x11 = h, x12 = i, x13 = j

Return

x10 = (g + h) − (i + j)

Step-by-step leaf procedure

leaf_calc:
    add x5, x10, x11   # x5 = g + h
    add x6, x12, x13   # x6 = i + j
    sub x10, x5, x6   # put result in x10
    ret              # return via x1

The procedure needs no stack frame: it calls no one and modifies only caller-saved registers. A larger leaf function may still need a stack frame for local data or saved registers (x8–x9 and x18–x27).

Common mistake: Saving every temporary register register in the callee is not required by the ABI; saved registers x8–x9 and x18–x27 are different. A procedure must restore callee-saved numeric registers that it changes.

Ch. 2 • Calls & stack

Non-leaf procedures

Lesson 2 / 9

A non-leaf procedure calls another procedure. A nested jal x1, target overwrites x1, so the calling procedure must preserve the return address if it needs to return to its own caller. It must also preserve any caller-saved values it needs after a call.

A function that calls another function

C source
long square(long x) {
    return x * x;
}
long addSquare(long n) {
    return square(n) + 3;
}
Educational RV64 assembly
# x10 = n
addSquare:
    addi x2, x2, -16
    sd x1, 8(x2)       # save caller RA
    jal x1, square    # result in x10
    addi x10, x10, 3
    ld x1, 8(x2)
    addi x2, x2, 16
    ret
square:
    mul x10, x10, x10
    ret

Stack frame layout

Higher address · old SP
8(x2) · saved x1 · 8 bytes
0(x2) · available slot · 8 bytes
Lower address · new SP

The frame is 16 bytes so x2 retains its 16-byte alignment at a call boundary. For recursion, each invocation creates a separate frame. When arguments are still needed after calling a function, save them in a callee-saved register (with preservation) or in the frame.

Ch. 2 • Address calculations

Arrays versus pointers

Lesson 3 / 9

In C, A[i] accesses an element by index. Pointer traversal instead advances a memory address. Both can describe the same memory operations. RISC-V registers hold addresses, so students must calculate byte offsets explicitly.

Array indexing

For long long A[], each element is 8 bytes.

address(A[i]) = base + i × 8
Pointer walk

Move from one 64-bit element to the next.

pointer = pointer + 8

Load A[i] using an index

# x10 = array base address
# x11 = index i
slli x5, x11, 3     # i * 8
add  x5, x10, x5    # &A[i]
ld   x6, 0(x5)     # A[i]

Walk through an array using a pointer

# x10 = pointer to first 64-bit item
# x11 = number of items
addi x5, x10, 0
slli x6, x11, 3
add  x6, x10, x6    # one-past-end
loop:
    bgeu x5, x6, done
    sd x0, 0(x5)   # *ptr = 0
    addi x5, x5, 8  # ptr++
    j loop
done:

Pointer-based code can eliminate repeated index scaling inside a loop, but optimizing compilers can often make indexed code just as efficient. Prefer clear and safe C code.

Distinguish element sizes: int usually uses 4 bytes in these exercises (lw/sw); 64-bit long long uses 8 (ld/sd).

Ch. 2 • Worked program

C sort and swap

Lesson 4 / 9

The Chapter 2 C sort example connects arrays, branches, loops and a procedure call. A leaf swap exchanges adjacent items; the sorting routine is non-leaf because it invokes swap.

Step 1 — Compare and swap adjacent elements

C program
void swap(long long v[], int k) {
    long long temp = v[k];
    v[k] = v[k + 1];
    v[k + 1] = temp;
}
RISC-V RV64 leaf swap
# x10 = v base, x11 = k
swap:
    slli x5, x11, 3
    add  x5, x10, x5
    ld   x6, 0(x5)
    ld   x7, 8(x5)
    sd   x7, 0(x5)
    sd   x6, 8(x5)
    ret

Step 2 — Build a sorting procedure

// Insertion-style adjacent-swap sort
void sort(long long v[], int n) {
    for (int i = 1; i < n; ++i) {
        int j = i - 1;
        while (j >= 0 && v[j] > v[j+1]) {
            swap(v, j);
            --j;
        }
    }
}

For each i, the inner loop moves the new item left while the pair is out of order. Sorting may require many calls to swap, so the surrounding non-leaf procedure must protect x1 and any live saved values. The sample is an adjacent-swap insertion sort, closely related to the teaching example.

Trace: Starting with [5, 2, 4], the first outer pass swaps to [2, 5, 4]. The next pass swaps [5, 4], producing [2, 4, 5].

Ch. 3 • Integer arithmetic

Binary addition & subtraction

Lesson 5 / 9

Binary addition uses the same column-by-column process as decimal, with carries of 0 or 1. Subtraction can be implemented by adding the two’s-complement negation of the subtrahend.

A − B = A + (NOT B + 1)

Worked example: 7 − 6 in 8 bits

  00000111   (+7)
+ 11111010   (−6 in two's complement)
-----------
  00000001   (+1, discard carry-out)

Always specify the register width. The signed 8-bit range is −128 through +127; the same arithmetic principle applies to 32-bit and 64-bit data.

Relevant RISC-V instructions

add  x5, x6, x7
sub  x5, x6, x7
addi x5, x6, -7

RISC-V integer add and sub keep the fixed-width result. They do not raise an arithmetic-overflow exception. When the mathematical result exceeds the signed range, the stored bit pattern wraps.

Ch. 3 • Integer arithmetic

Multiplication & division

Lesson 6 / 9

Shift-and-add multiplication uses the multiplier’s bits to decide which shifted partial products contribute to the result. Division finds a quotient and remainder and must handle signed/unsigned interpretations.

RISC-V multiply operations

mul   x5, x6, x7   # low 64 bits
mulh  x5, x6, x7   # upper 64 signed×signed
mulhu x5, x6, x7   # upper 64 unsigned×unsigned
mulhsu x5, x6, x7  # signed×unsigned upper

RISC-V divide operations

div  x5, x6, x7    # signed quotient
rem  x5, x6, x7    # signed remainder
divu x5, x6, x7    # unsigned quotient
remu x5, x6, x7    # unsigned remainder

For example, −17 divided by 5 yields a signed quotient of −3 and remainder −2. RISC-V truncates the signed quotient toward x0; the remainder follows the dividend’s sign.

Architectural corner case: Integer division by x0 has defined register results in RISC-V; it does not trap by default. The page’s basic RV64 teaching simulator models selected signed instructions, not the entire M extension.

Ch. 3 • Limits of representation

Signed overflow & saturation

Lesson 7 / 9

Signed overflow occurs when the exact mathematical result is outside the representable range. With n bits of two’s complement, signed values range from −2n−1 to 2n−1−1.

8-bit signed range: −128 to +127

Worked example: 120 + 20

  01111000  (120)
+ 00010100  (20)
----------
  10001100  (−116 when signed)

The mathematical result is 140, beyond +127. Fixed-width arithmetic keeps 10001100, interpreted as −116. Adding two positives and getting a negative signed result is a diagnostic sign of overflow.

Subtraction overflow

For signed subtraction, overflow is possible when operands have different signs and the result’s sign differs from the first operand.

Wrapping vs. saturation

Wraparound: Keep the low n bits. Saturation: Clamp to the maximum or minimum representable value. Chapter 3 contrasts saturating multimedia arithmetic with ordinary two’s-complement operations.

Ch. 3 • Real numbers

IEEE 754 floating-point format

Lesson 8 / 9

Floating-point represents very large and very small values with a sign, biased exponent and fraction. For normalized binary numbers:

value = (−1)s × (1.fraction)2 × 2E−bias
Single precision (32 bits)

1 sign bit · 8 exponent bits · 23 fraction bits · bias 127

Double precision (64 bits)

1 sign bit · 11 exponent bits · 52 fraction bits · bias 1023

Worked example: encode 6.5

6.5 decimal = 110.1 binary
           = 1.101 × 2²
Sign       = 0
Exponent   = 2 + 127 = 129 = 10000001
Fraction   = 101 followed by twenty zeros
IEEE 754   = 01000000110100000000000000000000
Hex        = 0x40D00000

Exponent field all zeros encodes zeros/subnormals; all ones encodes infinities and NaNs depending on the fraction. Rounding matters because most decimal fractions cannot be stored exactly in binary.

Ch. 3 • Accuracy & rounding

Floating-point operations

Lesson 9 / 9

Floating-point arithmetic is not the same as exact real-number arithmetic. IEEE 754 operations may round, lose small contributions, or overflow/underflow.

Adding floating-point values

  1. Compare exponents and shift the smaller significand to align.
  2. Add or subtract the significands.
  3. Normalize and round the result.
  4. Check for overflow, underflow, and special values.

Multiplying floating-point values

  1. Compute the output sign (XOR the sign bits).
  2. Add unbiased exponents.
  3. Multiply significands, normalize and round.

Example: exact binary fractions

1.5 = 1.1₂ × 2⁰
2.25 = 1.001₂ × 2¹
1.5 + 2.25 = 3.75
1.5 × 2.25 = 3.375
Precision lesson: At sufficiently large magnitudes, adding a tiny number may leave the stored floating-point value unchanged due to rounding. Floating point is generally not associative: (a+b)+c may differ from a+(b+c).

RISC-V floating point: The F and D extensions use floating-point registers (f0–f31) and instructions such as fadd.s, fmul.s, fadd.d. The built-in simulator currently supports integer instruction practice only.
